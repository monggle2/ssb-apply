# 지원사업 신청·면접 시스템 (시연용)

- 내부 시연·테스트용. 실제 신청자 정보·서류는 넣지 말 것
- 이 저장소는 공개 저장소이므로 코드만 둠. 신청 데이터는 구글 시트·드라이브에만 저장됨

## 구성

| 구분 | 위치 | 하는 일 |
|---|---|---|
| 신청 페이지 | GitHub Pages (`index.html`, `config.js`) | 신청자가 신청서 작성·서류 제출 |
| 담당자 화면 | 구글 앱스 스크립트 (`apps-script/Admin.html`) | 사업 설계(신청 항목·면접 질문), 접수함, 적/부 판정, 면접 기록지·점수 계산 |
| 신청 정보 | 구글 스프레드시트 | 사업설정, 신청목록, 면접기록, 서류판독, 사업자상태, 변경이력, 동의문구이력, 담당자, 사업별 `신청_사업명` 탭 |
| 제출 서류 | 구글 드라이브 | `신청서류_시트이름 / 사업명(사업ID) / 접수번호 상호` 폴더에 저장 |

## 설치 순서

### 1. 스프레드시트·스크립트 만들기
1. 구글 드라이브에서 새 스프레드시트 만들기 (예: `신청시스템_시연`)
2. 메뉴 **확장 프로그램 → Apps Script** 열기
3. 기본 `Code.gs` 내용을 지우고 이 저장소 `apps-script/Code.gs` 내용 붙여넣기
4. 파일 추가(＋ → 스크립트) 이름 `Catalog` → `apps-script/Catalog.gs` 내용 붙여넣기
5. 파일 추가(＋ → 스크립트) 이름 `Consent` → `apps-script/Consent.gs` 내용 붙여넣기
6. 파일 추가(＋ → HTML) 이름 `Admin` → `apps-script/Admin.html` 내용 붙여넣기
7. 왼쪽 **서비스 ＋** → **Drive API** 고르기 → **추가** (서류 글자 읽기에 필요)
8. 저장

### 2. 초기 설정
1. 스프레드시트 새로 고침 → 메뉴 **신청 시스템 → 1. 초기 설정** 실행
2. 권한 요청이 나오면 허용 (시트·드라이브 접근)
3. 결과: 시트 탭 4개(사업설정·담당자·신청목록·면접기록), 드라이브에 서류 폴더 생성, 실행한 계정이 담당자로 등록됨

### 3. 웹 앱 배포 (두 번)
Apps Script 화면 오른쪽 위 **배포 → 새 배포 → 유형: 웹 앱**

| 배포 | 다음 사용자로 실행 | 액세스 권한 | 용도 |
|---|---|---|---|
| 신청용 | 나 | 모든 사용자 | 신청 페이지가 접수할 때 쓰는 주소 |
| 담당자용 | 웹 앱에 액세스하는 사용자 | Google 계정이 있는 모든 사용자 | 담당자 화면 주소 |

- 각 배포 후 나오는 웹 앱 주소(`https://script.google.com/macros/s/…/exec`)를 따로 적어 둘 것
- 코드를 고친 뒤에는 **배포 → 배포 관리 → 수정(연필) → 버전: 새 버전**으로 두 배포 모두 갱신해야 반영됨

### 4. 담당자 추가
1. 시트 `담당자` 탭 A열에 담당자 구글 계정 이메일 추가
2. 스프레드시트를 그 담당자에게 **편집자**로 공유
3. 메뉴 **신청 시스템 → 2. 담당자에게 서류 폴더 공유** 실행
- 담당자용 주소는 접속한 사람 권한으로 실행되므로 시트·폴더 공유가 꼭 필요함

### 5. 신청 페이지(GitHub Pages) 켜기
1. 이 저장소 `config.js` 열기 → `window.API_URL = '';` 따옴표 안에 **신청용** 웹 앱 주소 넣고 저장(커밋)
2. 저장소 **Settings → Pages → Branch: main / (root) → Save**
3. 1~2분 뒤 `https://아이디.github.io/ssb-apply/` 주소로 열림

### 6. 첫 사업 만들기
1. **담당자용** 주소로 담당자 화면 열기
2. 오른쪽 `공개 신청 링크` 칸에 GitHub Pages 주소 넣고 **주소 저장**
3. 사업 선택 → **＋ 새 사업 만들기** → 이름·모듈·모집 기간·신청 코드 입력, **접수 중** 켜기 → **설계 저장**
4. 나온 공개 신청 링크(`…/ssb-apply/?p=사업ID`)로 신청 시험
5. **접수함** 탭에서 신청 내용·첨부 확인, 적/부 판정, 면접 기록지 작성

## 동작 메모
- 신청 페이지는 접수 중이고 모집 기간 안인 사업만 보여 줌
- 신청 코드를 넣은 사업은 코드가 맞아야 제출됨 (대소문자 구분 없음)
- 첨부 파일: PDF·사진·한글·워드·엑셀, 한 개 10MB 이하, 합계 25MB 이하
- 시연용을 켠 사업만 `예시 값 채우기` 버튼과 시연 안내가 보임
- 면접 점수
  - 여신 외: 영역 점수 = 받은 점수 합 ÷ (채점 문항 수 × 5) × 25, `해당 없음`은 계산에서 제외
  - 여신: 항목 점수 = 배점 × 받은 점수 ÷ 5, 가점 후보는 총점에서 제외
- 사업설정 시트의 `설정JSON` 칸은 담당자 화면에서만 고칠 것
- 개인(신용)정보 동의 문구: 모든 사업 공통. `Consent.gs`에서 고친 뒤 새 버전으로 배포
  - 신청자는 항목별 본문을 읽고 `동의합니다` 체크(또는 `모두 동의`). 동의서 파일 업로드 없음

## 사업 맞춤 설계
- 설계 화면 `02 신청 항목`
  - 기본 항목: 켜기·끄기, 필수 여부, 이름·안내 문구·선택지 수정
  - 영역마다 **모두 켜기 / 모두 끄기** (개인정보 동의 항목은 끄지 않음)
  - **＋ 이 영역에 새 항목**: 그 영역 안에 사업 전용 항목 추가
  - **＋ 새 항목 만들기**: 맨 아래 `추가 항목` 영역에 추가
- 새 항목 설정: 항목 이름, 안내 문구, 넣을 위치, 필수 여부, 칸(최대 10개)
  - 칸 형식: 짧은 글, 긴 글(최대 글자 수), 숫자(단위), 날짜, 목록에서 하나, 하나 선택(버튼), 여러 개 선택, 파일 첨부, 인터넷 주소, 이메일, 전화번호
  - 선택형은 선택지를 쉼표로 구분
- 새 항목은 신청 화면·검증·`신청_사업명` 탭·접수함에 기본 항목과 똑같이 반영
- 이미 접수된 신청이 있는 사업에서 새 항목을 삭제하면 그 내용은 접수함에서 안 보임 → 삭제 대신 끄기 권장 (원본은 `원본JSON`·서류 폴더에 남음)

## 사업자번호 확인과 매출 서류
- 신청 화면에서 사업자번호를 넣고 **확인** → 국세청 조회(같은 번호는 6시간 동안 저장된 결과 사용, 하루 5,000건 한도)
  - 폐업자·국세청에 없는 번호 → 제출 불가
  - 휴업자 → 제출 불가 (설계 화면 `04` **휴업자도 신청 허용**을 켜면 진행)
  - 계속사업자 → 사업자 유형 자동 선택(바꿀 수 없음), 매출 서류 칸 이름이 아래 서류로 바뀜
- 과세유형별 매출 서류
  - 개인·법인 일반과세자 / 개인 간이과세자 → 부가가치세 과세표준증명
  - 개인 면세사업자 → 부가가치세 면세사업자 수입금액증명
  - 법인 면세사업자 → 표준재무제표증명
  - 개인사업자 소득금액증명: 설계 화면 `04` **개인사업자는 소득금액증명도 인정**을 켜면 허용
- 개인·법인 구분은 사업자번호 가운데 두 자리(81~88이면 법인)
- 확인은 접수 서버에서 한 번 더 함 (화면을 우회해도 차단). 결과는 신청서와 `사업자상태` 시트에 저장
- 국세청 조회가 안 될 때(인증키 없음·한도 초과·장애)는 막지 않고 "확인 대기"로 받고, 자동 처리 때 다시 조회
- 시연용 사업에서 예시 번호(123-45-67890)는 국세청 조회 없이 "계속사업자(시연용)"로 처리
- 매출 읽기 (서류 종류를 먼저 알아본 뒤)
  - 과세표준증명: 과세기간 줄의 매출과세표준 **계**, 여러 기간이면 합계
  - 면세사업자 수입금액증명: **수입금액**, 여러 기간이면 합계
  - 소득금액증명: 종합소득세 **수입금액 줄의 사업** 칸
  - 표준재무제표증명: **표준손익계산서 I.매출액** (재무상태표·코드 001 제외)
  - 칸 순서가 섞여 읽힌 경우는 "(추정)"으로 표시하고 확인필요
- 자동 점검: 제출 대상 서류와 다른 서류면 확인필요, 인정하지 않는 소득금액증명은 탈락후보, 서류 매출과 신청서 연매출 비교, 과세기간 1년 미만 표시
- 매출 기간 (신청서)
  - 시작일~종료일 입력, 기본값 직전 연도 1/1~12/31
  - 그 해 중간 개업이면 시작일 = 개업일 (직접 고치면 유지)
- 매출 기간 대조 (서류 과세기간 vs 신청서 매출 기간)
  - 기간 안이면 통과 (중간 개업 후 서류 시작 → 문제 없음)
  - 개업일·시작일보다 늦은 달부터 시작 → 확인필요 (앞 기간 누락)
  - 종료일보다 이른 달에 끝남 → 확인필요 (뒤 기간 누락)
  - 기간 밖 포함 → 확인필요

## 심사 마무리
- 심사 단계: 접수 → 서류 검토(적격·보완 요청·보완 제출·부적격) → 면접 → 최종 결과(선정·예비·탈락)
- **보완 제출**: 적/부 탭에서 `보완 요청`으로 판정하고 `신청자에게 보일 보완 요청 내용`을 적어 저장하면 그 신청 전용 링크(`…/ssb-apply/?fix=접수번호&t=…`)가 만들어짐
  - 담당자가 링크를 문자·카톡으로 전달 → 신청자가 서류 칸별로 파일과 메모를 올림
  - 올린 파일은 같은 신청 폴더 안 `보완_날짜` 폴더에 저장되고 첨부 탭에 `보완`으로 표시, 상태는 `보완 제출`, 자동 처리가 다시 읽음
  - 링크는 상태가 `보완 요청`·`보완 제출`일 때만 열림 (적격·부적격으로 판정하면 닫힘)
- **위원별 면접 채점**: 면접 기록지 탭에서 `＋ 위원 추가` → 위원 이름과 점수 입력 → 위원마다 저장
  - 위원별 영역 점수·총점 표, 평균, 최고-최저 차이, 위원 간 2점 이상 차이 나는 문항 표시
  - 최종 면접 점수는 위원 평균 (`신청목록`의 면접총점·면접위원수, `면접기록` 시트는 위원마다 한 줄)
- **결과 탭**: 적격 판정을 받은 신청을 면접 평균 점수순으로 표시
  - 선정 인원·예비 인원을 넣고 `점수순으로 채우기` → 직접 고친 뒤 `결과 저장`
  - 동점자·면접 점수 없는 적격자 안내, 결과는 `신청목록`의 최종결과·최종결과일시·최종결과자에 저장
  - 접수함에서 `최종 결과` 필터로 선정·예비·탈락·미정만 볼 수 있음

## 자동 처리 (새 신청 자동 읽기)
- 켜기: 시트 메뉴 **신청 시스템 → 3. 자동 처리 켜기** (처음 한 번 권한 허용 필요)
- 5분마다 `처리상태`가 비었거나 `대기`인 신청을 순서대로 처리: 국세청 사업자 상태 조회 → 서류 글자 읽기 → 항목 정리 → 자동 점검 결과 기록
- `신청목록` 시트에 기록되는 칸: 사업자번호, 처리상태(대기·완료·오류), 처리시도, 처리일시, 처리메모, 자동판정, 탈락후보, 확인필요, 자동사유
- 실패하면 다음 회차에 다시 시도, 3번 실패하면 `오류`로 멈춤 → 담당자 화면 적/부 탭 **자동 처리 다시 하기**
- 한 번 실행은 4분 30초까지. 남은 신청은 다음 회차에 이어서 처리
- 개인 gmail 계정은 자동 실행 시간이 하루 90분, 파일 변환이 하루 2,000건까지라 신청이 많으면 기관 Workspace 계정으로 운영 권장

## 안정화 메모
- 같은 신청 중복 저장 방지: 신청서마다 제출ID를 붙여, 응답이 끊겨 다시 제출해도 한 건만 저장
- 접수번호는 날짜 + 임의 5자리, 저장 전 중복 확인
- 파일 저장은 잠금 밖에서 처리해 마감 직전 동시 제출에도 대기 시간이 길어지지 않음
- `변경이력` 시트: 사업 만들기·수정, 적/부 판정, 면접 기록, 자동 처리 다시 요청을 누가·언제·무엇을 바꿨는지 기록
- 동의 기록: `신청목록`의 동의버전·동의일시, 동의 문구 원문은 `동의문구이력` 시트 (버전은 문구 내용으로 자동 생성)
- 신청 화면 임시 저장: 이 브라우저에만 7일 보관, 첨부 파일·생년월일은 저장하지 않음, 제출하면 삭제
- 마감 시각: 설계 화면 모집 마감 옆 시각 (비우면 23:59)
- 접수 건이 있는 사업의 설계를 열면 기준 변경 경고 표시

## 자동 적/부 점검 (참고용)
- 접수함 → 적/부 판정 탭 위쪽에 표시. 판정은 탈락후보 / 확인필요 / 정상, 최종 판정은 담당자
- 점검 기준은 설계 화면 `04 자동 적/부 점검 기준`에서 사업별로 설정 (비우면 그 점검은 안 함)
  - 개업일 기준, 최소 업력, 연매출 상한, 서류 발급 기준(개월), 대상 지역, 제외 사업자 유형, 제외 업종 키워드
- 신청서 점검: 사업자번호 형식·비영리(가운데 80·82~85·89), 같은 사업자번호 중복, 타 지원 중복, 필수 서류 누락, 동의 누락
- 서류 점검: `서류 글자 읽기` 버튼 → 구글 드라이브 OCR로 PDF·사진·워드 서류 글자를 읽어 `서류판독` 시트에 저장
  - 사업자등록증명: 서류 종류, 사업자번호·대표자·개업일 대조, 열람용 문구, 발급일
  - 과세표준증명: 서류 종류(소득금액증명 불인정), 연매출 금액 대조, 발급일
  - 통장 사본: 예금주가 대표자·상호와 같은지
  - 상품·사업장 사진, 한글(hwp)·엑셀 파일은 읽지 않음
  - 읽은 글자는 항목별로 나눠 서류 종류별 시트에 보관: `판독_사업자등록`(등록번호·상호·대표자·개업연월일·법인등록번호·소재지·업태·종목·발급사유·발급일·발급기관), `판독_매출증빙`(서류종류·사업자번호·상호·대표자·과세기간·매출 합계·발급일), `판독_통장`(은행·계좌번호·예금주). 원문은 `서류판독` 시트
  - 적/부 탭 `서류 판독 결과`: 항목별 표에 신청서 값과 같음/다름 표시
- 사업자 상태: `사업자 상태 조회` 버튼 → 국세청 사업자등록 상태조회 API(공공데이터포털)로 계속·휴업·폐업 확인, `사업자상태` 시트에 저장
  - 폐업자·미등록 → 탈락후보, 휴업자 → 확인필요, 신청서 사업자 유형과 과세유형이 다르면 확인필요
  - 공공데이터포털 인증키(Decoding)를 Apps Script **프로젝트 설정 → 스크립트 속성**에 이름 `NTS_KEY`로 저장 (코드·GitHub에 넣지 말 것)
- 제외 업종 키워드와 서류 점검 규칙은 기존 `심사도우미` 규칙을 참고함
- 직인 색·모양, 사진 중복 판단은 구글 OCR로 할 수 없어 빠짐

- 시트·드라이브 공유 범위를 담당자로 한정했는지 확인
