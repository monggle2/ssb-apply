# 지원사업 신청·면접 시스템 (시연용)

- 내부 시연·테스트용. 실제 신청자 정보·서류는 넣지 말 것
- 이 저장소는 공개 저장소이므로 코드만 둠. 신청 데이터는 구글 시트·드라이브에만 저장됨

## 구성

| 구분 | 위치 | 하는 일 |
|---|---|---|
| 신청 페이지 | GitHub Pages (`index.html`, `config.js`) | 신청자가 신청서 작성·서류 제출 |
| 담당자 화면 | 구글 앱스 스크립트 (`apps-script/Admin.html`) | 사업 설계(신청 항목·면접 질문), 접수함, 적/부 판정, 면접 기록지·점수 계산 |
| 신청 정보 | 구글 스프레드시트 | 사업설정, 신청목록, 면접기록, 서류판독, 사업자상태, 담당자, 사업별 `신청_사업명` 탭 |
| 제출 서류 | 구글 드라이브 | `신청서류_시트이름 / 사업명(사업ID) / 접수번호 상호` 폴더에 저장 |

## 설치 순서

### 1. 스프레드시트·스크립트 만들기
1. 구글 드라이브에서 새 스프레드시트 만들기 (예: `신청시스템_시연`)
2. 메뉴 **확장 프로그램 → Apps Script** 열기
3. 기본 `Code.gs` 내용을 지우고 이 저장소 `apps-script/Code.gs` 내용 붙여넣기
4. 파일 추가(＋ → 스크립트) 이름 `Catalog` → `apps-script/Catalog.gs` 내용 붙여넣기
5. 파일 추가(＋ → 스크립트) 이름 `Consent` → `apps-script/Consent.gs` 내용 붙여넣기
6. 파일 추가(＋ → HTML) 이름 `Admin` → `apps-script/Admin.html` 내용 붙여넣기
7. 왼쪽 **서비스 ＋** → **Drive API** 고르기 → **추가** (서류 글자 읽기에 필요)
8. 저장

### 2. 초기 설정
1. 스프레드시트 새로 고침 → 메뉴 **신청 시스템 → 1. 초기 설정** 실행
2. 권한 요청이 나오면 허용 (시트·드라이브 접근)
3. 결과: 시트 탭 4개(사업설정·담당자·신청목록·면접기록), 드라이브에 서류 폴더 생성, 실행한 계정이 담당자로 등록됨

### 3. 웹 앱 배포 (두 번)
Apps Script 화면 오른쪽 위 **배포 → 새 배포 → 유형: 웹 앱**

| 배포 | 다음 사용자로 실행 | 액세스 권한 | 용도 |
|---|---|---|---|
| 신청용 | 나 | 모든 사용자 | 신청 페이지가 접수할 때 쓰는 주소 |
| 담당자용 | 웹 앱에 액세스하는 사용자 | Google 계정이 있는 모든 사용자 | 담당자 화면 주소 |

- 각 배포 후 나오는 웹 앱 주소(`https://script.google.com/macros/s/…/exec`)를 따로 적어 둘 것
- 코드를 고친 뒤에는 **배포 → 배포 관리 → 수정(연필) → 버전: 새 버전**으로 두 배포 모두 갱신해야 반영됨

### 4. 담당자 추가
1. 시트 `담당자` 탭 A열에 담당자 구글 계정 이메일 추가
2. 스프레드시트를 그 담당자에게 **편집자**로 공유
3. 메뉴 **신청 시스템 → 2. 담당자에게 서류 폴더 공유** 실행
- 담당자용 주소는 접속한 사람 권한으로 실행되므로 시트·폴더 공유가 꼭 필요함

### 5. 신청 페이지(GitHub Pages) 켜기
1. 이 저장소 `config.js` 열기 → `window.API_URL = '';` 따옴표 안에 **신청용** 웹 앱 주소 넣고 저장(커밋)
2. 저장소 **Settings → Pages → Branch: main / (root) → Save**
3. 1~2분 뒤 `https://아이디.github.io/ssb-apply/` 주소로 열림

### 6. 첫 사업 만들기
1. **담당자용** 주소로 담당자 화면 열기
2. 오른쪽 `공개 신청 링크` 칸에 GitHub Pages 주소 넣고 **주소 저장**
3. 사업 선택 → **＋ 새 사업 만들기** → 이름·모듈·모집 기간·신청 코드 입력, **접수 중** 켜기 → **설계 저장**
4. 나온 공개 신청 링크(`…/ssb-apply/?p=사업ID`)로 신청 시험
5. **접수함** 탭에서 신청 내용·첨부 확인, 적/부 판정, 면접 기록지 작성

## 동작 메모
- 신청 페이지는 접수 중이고 모집 기간 안인 사업만 보여 줌
- 신청 코드를 넣은 사업은 코드가 맞아야 제출됨 (대소문자 구분 없음)
- 첨부 파일: PDF·사진·한글·워드·엑셀, 한 개 10MB 이하, 합계 25MB 이하
- 시연용을 켠 사업만 `예시 값 채우기` 버튼과 시연 안내가 보임
- 면접 점수
  - 여신 외: 영역 점수 = 받은 점수 합 ÷ (채점 문항 수 × 5) × 25, `해당 없음`은 계산에서 제외
  - 여신: 항목 점수 = 배점 × 받은 점수 ÷ 5, 가점 후보는 총점에서 제외
- 사업설정 시트의 `설정JSON` 칸은 담당자 화면에서만 고칠 것
- 개인(신용)정보 동의 문구: 모든 사업 공통. `Consent.gs`에서 고친 뒤 새 버전으로 배포
  - 신청자는 항목별 본문을 읽고 `동의합니다` 체크(또는 `모두 동의`). 동의서 파일 업로드 없음

## 자동 적/부 점검 (참고용)
- 접수함 → 적/부 판정 탭 위쪽에 표시. 판정은 탈락후보 / 확인필요 / 정상, 최종 판정은 담당자
- 점검 기준은 설계 화면 `04 자동 적/부 점검 기준`에서 사업별로 설정 (비우면 그 점검은 안 함)
  - 개업일 기준, 최소 업력, 연매출 상한, 서류 발급 기준(개월), 대상 지역, 제외 사업자 유형, 제외 업종 키워드
- 신청서 점검: 사업자번호 형식·비영리(가운데 80·82~85·89), 같은 사업자번호 중복, 타 지원 중복, 필수 서류 누락, 동의 누락
- 서류 점검: `서류 글자 읽기` 버튼 → 구글 드라이브 OCR로 PDF·사진·워드 서류 글자를 읽어 `서류판독` 시트에 저장
  - 사업자등록증명: 서류 종류, 사업자번호·대표자·개업일 대조, 열람용 문구, 발급일
  - 과세표준증명: 서류 종류(소득금액증명 불인정), 연매출 금액 대조, 발급일
  - 통장 사본: 예금주가 대표자·상호와 같은지
  - 상품·사업장 사진, 한글(hwp)·엑셀 파일은 읽지 않음
  - 읽은 글자는 항목별로 나눠 서류 종류별 시트에 보관: `판독_사업자등록`(등록번호·상호·대표자·개업연월일·법인등록번호·소재지·업태·종목·발급사유·발급일·발급기관), `판독_매출증빙`(서류종류·사업자번호·상호·대표자·과세기간·매출 합계·발급일), `판독_통장`(은행·계좌번호·예금주). 원문은 `서류판독` 시트
  - 적/부 탭 `서류 판독 결과`: 항목별 표에 신청서 값과 같음/다름 표시
- 사업자 상태: `사업자 상태 조회` 버튼 → 국세청 사업자등록 상태조회 API(공공데이터포털)로 계속·휴업·폐업 확인, `사업자상태` 시트에 저장
  - 폐업자·미등록 → 탈락후보, 휴업자 → 확인필요, 신청서 사업자 유형과 과세유형이 다르면 확인필요
  - 공공데이터포털 인증키(Decoding)를 Apps Script **프로젝트 설정 → 스크립트 속성**에 이름 `NTS_KEY`로 저장 (코드·GitHub에 넣지 말 것)
- 제외 업종 키워드와 서류 점검 규칙은 기존 `심사도우미` 규칙을 참고함
- 직인 색·모양, 사진 중복 판단은 구글 OCR로 할 수 없어 빠짐

## 실제 접수 전 확인할 것
- 대표자 생년월일(7자리)·통장 사본·신용정보 동의서 수집은 기관 개인정보 규정 검토 필요
- `Consent.gs`의 동의 문구를 기관 양식으로 교체
- 시트·드라이브 공유 범위를 담당자로 한정했는지 확인
- 시연용 끄기, 시연 중 들어간 예시 신청 정리
